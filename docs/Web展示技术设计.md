# LeoSentry · Web 展示（今日概览）

> 范围：局域网浏览器打开软路由上的管理页，查看当天各设备在干什么。
> 管控策略、设备改名、登录认证、历史报表不在本文范围。

## 1. 做这个页面的初衷

LeoSentry 的目标是让家长对家里的网络**一目了然**：谁在线、在玩什么、玩了多久、什么时段、流量大不大。
技术上能可靠识别的，才做成可筛选的维度；识别不了的（HttpDNS、无域名）如实标成「未识别」，不假装知道。

首页因此按四个问题组织，而不是做成一张明细表：

| 问题 | 页面上的位置 |
| --- | --- |
| 现在谁在干什么？ | 「正在进行」（最近 5 分钟） |
| 今天有没有该留意的？ | 「关注提醒」：游戏过长、连续游戏、刷短视频、深夜娱乐 |
| 每台设备今天怎么过的？ | 设备卡片：上网 / 娱乐 / 流量 + 类别条 + 24 小时时间线 + 主要应用 |
| 全家合在一起是什么结构？ | 上网时段热力图、行为类别条、应用与网站表 |

筛选是**组合**的：时段 × 类别 × 设备。点「晚上 + 游戏」就能看到晚上谁在玩游戏；点某台设备看它自己的一天。
刷新按钮重新向路由器要一次快照，切换筛选不再请求。

## 2. 服务端做 / 浏览器做

路由器 CPU 和闪存都紧，原则是：**必须扫库、必须分类的事情做一次；排序、筛选、画图全部在手机/电脑上做。**

| 在 Go 服务端 | 在浏览器 |
| --- | --- |
| 扫一遍 `today.db`（缺域名的行按同目标 IP 最近一条补全） | 按时段 / 类别 / 设备筛选 |
| 用内嵌规则库把域名归到应用和类别 | 排序、搜索、展开 |
| 按「设备 × 10 分钟桶 × 应用」聚合并去重活跃周期 | 组合出时长、流量、热力图、会话 |
| 结果 JSON 缓存（库版本变化或超过 20 秒才重算），预 gzip | SVG 时间线 / 小时柱，无第三方库 |
| 静态文件 embed 进二进制，启动时预压缩，ETag 304 | 响应式布局（侧栏 / 抽屉） |

一次扫描大约扫描当天全部明细（当前约一千行、一百多毫秒），之后相同数据的请求直接返回缓存（约 8 ms）或 304。
浏览器拿到的是紧凑整数数组，不是逐行明细。

## 3. 访问方式

- 地址：只监听 LAN 接口上的 IPv4（默认 `http://192.168.1.1:8088/`），不绑 `0.0.0.0`，WAN 访问不到。
- 配置：`http_port`（默认 8088，`0` 关闭）、`http_address`（留空则用 `lan_device` 上的地址）。
- 页面无登录。局域网里的孩子也能打开——上管控功能之前需要补认证。

## 4. API

`GET /api/v1/overview/today`

响应是一份「今日快照」，字段含义见 `internal/analyzer/activity/overview.go`。要点：

- 时间一律按路由器时区（`tzOffset`），不依赖访问设备的时区。
- `intervalSeconds`：一个采集周期的秒数。`periods × intervalSeconds / 60` = 活跃分钟。
- 四张事实表：

  | 字段 | 一行 | 用途 |
  | --- | --- | --- |
  | `deviceBuckets` | `[设备, 时段, 周期, 上行, 下行]` | 设备上网时长、流量（时段互不重叠，可直接相加） |
  | `categoryBuckets` | `[设备, 时段, 类别, 周期]` | 某类行为的时长 |
  | `entBuckets` | `[设备, 时段, 周期]` | 娱乐类（游戏/短视频/视频/直播）去重后的时长 |
  | `appBuckets` | `[设备, 时段, 应用, 周期, 上行, 下行]` | 应用表 |
  | `recent` | `[设备, 应用, 周期]` | 「正在进行」 |

  同一分钟里游戏和视频可以同时有流量，所以**不能**把各应用的周期数加起来当设备时长，三个层级分别给出已去重的周期数。

- `Cache-Control: no-cache` + `ETag`。刷新按钮用 `fetch(..., { cache: 'no-cache' })`。

## 5. 分类规则

内嵌在 `assets/rules/`，启动时读入：

- 娱乐：游戏、短视频、视频、直播。
- 其他可识别：音乐、社交、学习、购物、资讯、系统、物联网、广告。
- 规则未命中的主域名归「其他」并标「网站」；完全没有域名的归「未识别」。
- 系统 / 物联网 / 广告 / 未识别视为后台流量：判断「正在做什么」、列主要应用时降低优先级。

域名匹配：先 glob 模式，再最长后缀。部分游戏走 HttpDNS，dnsmasq 看不到域名，会落在「未识别」——扫描时按目标 IP 回填最近一次见过的域名，能补一部分。

## 6. 页面结构

后台框架：左侧导航（手机上汉堡抽屉）。今日概览可用；设备管理、管控策略、历史报表、系统设置为占位。

今日概览从上到下：

1. 筛选：全天 / 上午 / 下午 / 晚上 / 深夜 / 最近 1 小时；全部 / 娱乐 / 各类别；设备下拉。
2. 四个数字：活跃设备、娱乐（或所选类别）时长、游戏最多的那台、流量。
3. 正在进行 + 关注提醒。
4. 设备卡片（可按时长 / 娱乐 / 游戏 / 流量 / 最近活跃 / 名称排序）。无记录的设备收成一行，避免占满屏幕。
5. 设备 × 时段热力图：颜色是该格的主要行为，深浅是活跃程度。电脑按 10 分钟一格，手机按小时一格。
6. 行为类别条（点击筛选）+ 应用表（搜索、排序）。
7. 点设备打开详情：每小时柱状图、连续上网时段、类别、应用、IP/MAC。

电脑：侧栏 + 多列卡片。手机：单列、筛选芯片横向滑动、详情从底部滑出。跟随系统浅色 / 深色。

## 7. 统计口径（页面底部也有）

- 一个采集周期内有超过阈值的流量，计为活跃 1 个周期（默认 1 分钟）。
- 每分钟不足 `min_flow_kb_per_min`（默认 8 KB）的连接不入库，用来去掉心跳。
- 多台设备同时使用时，时长按设备分别累计，全家合计会大于墙上的时钟。
- 时间线从当天 03:00（统计日切换）起算。
