# LeoSentry · Web 展示与管控

> 范围：局域网里的管理页、登录、今日/昨日概览、设备、策略，以及策略如何变成 nft 规则。
> 流量怎么采集、明细怎么落盘，见 [采集层技术设计.md](采集层技术设计.md)。

管理页编译进二进制，用 hash 路由，没有单独的前端构建步骤。四个页面：

| 路由 | 页面 | 做什么 |
| --- | --- | --- |
| `#/overview` | 每日概览 | 今天或昨天谁在上网、用了什么、用了多久 |
| `#/policies` | 管控策略 | 时长、时段、暂停、临时延长、模板 |
| `#/devices` | 设备管理 | 起名、查看主机名、历史 IP、是否在线 |
| `#/system` | 系统设置 | 类别名单、日历、采集间隔、密码、重启 |

电脑是左侧导航，手机是抽屉。配色跟随系统的浅色或深色。

## 1. 登录

除 `POST /api/v1/login` 以外，所有 `/api/` 请求都要带会话 Cookie `leosentry_session`。静态页面本身不检查登录，数据接口返回 401 时前端再显示登录框。

- 首次启动写入默认密码 `123456`（`internal/store/auth.go`）。密码以随机盐加 SHA-256 存在 `policy.db`，长度 4～64 个字符。
- 登录成功后发 32 字节随机令牌，HttpOnly、SameSite=Lax，有效期 30 天。经 HTTPS 登录时 Cookie 带 Secure。令牌只在进程内存里，重启服务后全部失效。
- 未配置密码库时（仅测试或本机预览）不拦截 API。

监听地址是 `:端口`，绑在全部网卡上，例如 `:8088` 和 `:8443`。`http_port` 默认 `8088`，`https_port` 默认 `8443`，为 `0` 时不监听对应协议。两个端口和证书路径都可以在「系统设置 → 端口与证书」里修改，端口必须是 0 到 65535 的整数，不能相同，也不能同时为 0。和当前进程已加载的值不同时，确认框会说明要重启，确认后自动重启。`tls_cert` 与 `tls_key` 默认为空，不启用 HTTPS。下次启动检查证书和端口；检查失败则只保留还能监听的那一路，并在设置页显示原因。

## 2. 服务端做 / 浏览器做

路由器只做必须碰数据库和内核的事。排序、筛选、搜索和画图在浏览器里完成，页面不依赖第三方脚本。

| 在 Go 服务端 | 在浏览器 |
| --- | --- |
| 扫描 `today.db` 或 `prev.db`，给缺域名的行补上同一目标 IP 最近一次域名 | 按时段、类别、设备筛选 |
| 用当前规则库分类 | 排序、搜索、展开 |
| 聚成「设备 × 10 分钟 × 应用」，并按设备、类别、娱乐分别去重 | 时长、流量、热力图、连续时段 |
| JSON 缓存：库版本或设备名版本变了，或超过 20 秒，才重算；响应预 gzip | SVG 图表 |

`GET /api/v1/overview/today?day=yesterday` 读前一个统计日。没有 `prev.db`，或它不属于昨天时，页面是空的。`day` 不是 `yesterday` 时按今天处理。

时间用路由器时区（响应里的 `tzOffset`），不跟访问者的电脑走。`intervalSeconds` 是采集周期秒数，活跃分钟 = 周期数 × `intervalSeconds` / 60。

四张事实表都是整数数组，下标指向 `categories`、`apps`、`devices`：

| 字段 | 一行 | 用途 |
| --- | --- | --- |
| `deviceBuckets` | `[设备, 时段, 周期, 上行, 下行]` | 设备时长和流量。时段不重叠，可以相加 |
| `categoryBuckets` | `[设备, 时段, 类别, 周期]` | 某一类的时长 |
| `entBuckets` | `[设备, 时段, 周期]` | 游戏、短视频、视频、直播去重后的娱乐时长 |
| `appBuckets` | `[设备, 时段, 应用, 周期, 上行, 下行]` | 应用表 |
| `recent` | `[设备, 应用, 周期]` | 最近 5 分钟，供「正在进行」 |

同一分钟里游戏和视频可以同时有流量，所以不能把各应用的周期数加起来当成这台设备的上网时长。

缓存头是 `Cache-Control: no-cache` 加 `ETag`。内容未变时返回 304。刷新按钮使用 `fetch(..., { cache: 'no-cache' })`。

字段定义在 `internal/analyzer/activity/overview.go`。

## 3. 每日概览

首页按四个问题排，而不是一张原始明细：

| 问题 | 位置 |
| --- | --- |
| 现在谁在干什么？ | 「正在进行」，只统计相对当前时刻的最近 5 分钟。看昨天时这段通常是空的 |
| 今天有没有该留意的？ | 「关注提醒」：游戏过长、连续游戏、刷短视频、深夜娱乐 |
| 每台设备怎么过的？ | 卡片：上网 / 娱乐 / 流量、类别条、时间线、主要应用 |
| 合在一起是什么结构？ | 热力图、类别条、应用与网站表 |

可以在「今天」和「昨天」之间切换。筛选是组合的：全天 / 上午 / 下午 / 晚上 / 深夜 / 最近 1 小时 × 类别 × 设备。切换筛选不再请求。

设备卡片可按时长、娱乐、游戏、流量、最近活跃、名称排序。没有记录的设备收成一行。热力图的颜色是该格的主要行为，深浅是活跃程度；电脑按 10 分钟一格，手机按小时。点开设备可以看到每小时流量、连续上网时段、类别、应用和 IP / MAC。

在线状态来自 conntrack，大约每 10 秒刷新，和流量明细不是同一条数据。conntrack 会忽略路由器自己的 LAN 地址。24 小时没有连接的设备从这张状态表里去掉。

统计口径：

- 一个采集周期里有超过阈值的流量，计为活跃 1 个周期（默认 1 分钟）。
- 每分钟合计不足 `min_flow_kb_per_min`（默认 8 KB）的「设备 → 目标」不入库，用来去掉心跳。
- 多台设备同时使用时，时长按设备分别累计，全家加总可以大于墙上的时钟。
- 时间从统计日切换时刻起算，默认当天 03:00。

## 4. 设备管理

`devices.db` 不随统计日删除。采集到 MAC 时记下首次出现、最近出现和用过的 IPv4。新设备或新地址马上写入；同一地址的 `last_seen` 按小时节流，减少闪存写入。

页面把三份信息合成一台设备：账本里的名字和历史 IP、DHCP / 邻居表里的当前主机名，以及 conntrack 的在线状态。名字最长 40 个字符，空名字表示沿用主机名或地址。

`GET /api/v1/devices` 返回列表，`PATCH /api/v1/devices/{id}` 修改名字。`id` 是 MAC。

## 5. 分类规则

内置规则在 `assets/rules/`，编译进二进制。`categories/default.json` 定义类别，`games/default.json` 以及分类文件里的 `apps` 提供域名。启动时全部读入：

- 娱乐：游戏、短视频、视频、直播。
- 其他：音乐音频、社交聊天、学习教育、购物生活、资讯搜索、系统与应用商店、智能设备、广告统计。
- 有域名但规则未命中：归「其他」，按主域名当成一个网站。
- 没有域名：归「未识别」。
- 系统、智能设备、广告、未识别在「正在做什么」和主要应用里降低优先级。

匹配顺序：通配（`*`）优先，然后最长域名后缀。用户添加的 IPv4 用精确地址匹配。扫描明细时，若本行没有域名，会借用当天同一目标 IP 最近一条有域名的记录，长连接在 DNS 过期后仍能归类。

页面上的增删相对内置规则保存，不改二进制里的文件。同一条值可以从内置类别挪到另一个类别。添加上限 400 条。保存后分类器立刻换新，下一次概览和策略检查用新规则。也可以导出或导入整份 JSON（上限 256 KB）。

## 6. 管控策略

一台设备一份策略，存在 `policy.db`，按 MAC 而不是按当天的 IP。

**每日上限**最多 8 条。每条选择一类日期，并填写游戏、视频、上网三者中的至少一项，单位是分钟，单项不超过 1440。上网时长若填写了，游戏和视频不能比它更长。某一项留空表示不限制这一项。

**时段**最多 12 段。每段有开始和结束；结束早于开始表示跨到次日，例如 21:30–07:00。一段里可以禁止上网、禁止游戏、禁止视频。禁止上网时，这一段不再单独标游戏或视频。

日期类型的优先级：暑假 / 寒假，然后指定星期，然后法定工作日 / 法定休息日，最后是每天。同一天不能同时被两套上限或两段互相打架的时段选中。

判定顺序：

1. 未启用，且没有暂停、没有未过期的延长：不限制。
2. 已暂停：禁止全部外网。
3. 临时延长未到期：这期间不看时长和时段。延长 1～180 分钟，暂停时不能延长。
4. 今日上网分钟达到上限：禁止全部外网。
5. 当前落在「禁止上网」的时段里：禁止全部外网。
6. 否则，时段里禁止的游戏/视频，以及已经达到的游戏/视频上限，合并成局部拦截。

分钟数来自 `today.db`：同一采集周期里不论有多少条流量，只计 1 分钟。游戏只计类别为游戏的周期；视频把视频、短视频、直播合在一起。没有启用管控的设备不扫描。

策略数据损坏时，这台设备先按禁止上网处理。

自动检查默认每 5 分钟一次（`policy_interval`）。保存策略、暂停、延长、改日历都会马上再检查一次。因此时长用尽后，最坏要等到下一次检查才下发，不是采集周期一结束就断网。

一套时长和时段可以存成模板，再套到其他设备。模板不包含暂停和临时延长。

### 日历

内置 `assets/calendar/cn-2026.json`（国务院办公厅 2026 年节假日安排）。某一年还没导入时，按周一到周五工作、周六日休息。页面可以改暑假和寒假；若已有策略引用了暑假或寒假，不能把对应区间清空。导入的 JSON 若带寒暑假，会覆盖页面上的区间。模板下载走 `GET /api/v1/policies/calendar/template`。

时长用的「今天」是统计日，时段用的是墙上的日历日。跨过凌晨、但还没到 03:00 时，两者不是同一天，所以判定同时看统计日、日历今天和日历昨天。

### 下发到 nftables

`inet leosentry` 在启动时一次性装好计数规则和丢弃规则。之后只增删集合元素；元素没变就不写 netlink。

| 集合 | 内容 |
| --- | --- |
| `block_all` | 要完全断网的设备 IPv4 |
| `block_all_mac` | 这些设备的 MAC，转发路径上的 IPv6 也会被丢掉 |
| `block_game` / `block_video` | 只限制游戏或视频的设备 IPv4 |
| `game_dst` / `video_dst` | 当前 DNS Map 里能归到游戏，或归到视频/短视频/直播的目标 IPv4 |

局部拦截是「设备地址 × 目标地址」。目标集合来自这一刻的 DNS 观察，不是历史明细里出现过的全部地址。HttpDNS 或加密 DNS 得到的服务器不在里面，流量仍能通过。设备当前没有 IPv4 时，局部规则要等它有地址后的下一次检查；完全断网仍会写入 MAC。

同一台设备只进入一种拦截：全断、禁视频、禁游戏三者取当前判定的结果。全断优先。

这些规则挂在 `forward`、优先级 -10，早于 fw4。桥上的局域网互访不进这条链。

防火墙更新失败时保留上一份集合，并在页面上说明，下次检查再试。

## 7. 系统设置里会立刻影响运行的项

| 设置 | 生效时机 |
| --- | --- |
| 采集周期 | 保存后立刻改采集循环，并写入 `policy.db`。范围 1～3600 秒 |
| 忽略小流量 | 保存后立刻生效。单位 KB/分钟，建议 4～16，默认 8，`0` 表示全部记录。低于该速度的「设备 → 目标」不入库，用来去掉心跳 |
| 策略检查间隔 | 保存后立刻改下一次等待。范围同上 |
| 统计日切换 | 写入数据库，下次进程启动后才改日切时刻。页面会标成待生效 |
| HTTP / HTTPS 端口、证书 | 写入数据库。与当前已加载的端口或证书不同时，确认后自动重启。端口必须是 0 到 65535 的整数 |
| 类别名单 | 保存后立刻替换内存中的规则 |
| 重启 | 约 1 秒后执行已安装的 init 脚本 `restart`。当前进程先按正常退出补写流量、关掉 nft 表，再由 procd 拉起。没执行过 `install` 时页面不能重启 |

UCI 文件里的同名项仍然是首次安装的默认值。进程启动时，数据库里保存过的采集周期、忽略小流量、策略间隔、统计日和 HTTPS 证书路径会盖过 UCI。
